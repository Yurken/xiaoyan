# PDF 选择、缩放与笔记保存

桌面阅读器与导航缩略图共享同一 PDF 文档的绘制队列，同时最多执行两个任务。调度时重新计算视区优先级，可见页优先于邻页，导航任务最后执行。取消运行中的任务后，必须等任务实际结束才释放槽位。

阅读器保留最近使用的页面位图及文本层，通常最多八页；当前观察窗口中的页面固定保留，因此特别大的视窗可能超过八页。回收远页时保留页面尺寸，重新进入后恢复内容。每张位图限制为最长边 4096 像素、总计 1200 万像素，大尺寸 PDF 允许低于 1x 栅格化以遵守上限。此限制不涵盖 PDF.js 内部文档数据和导航缩略图，也不代表进程总内存上限。

触控板缩放保留完整精度的小增量，每帧最多更新一次显示比例，停止手势 160ms 后再请求高清重绘。缩放围绕指针所在的 PDF 位置调整滚动，工具栏缩放使用阅读视窗中心；到达滚动边界时仍受浏览器滚动范围限制。普通滚动保留浏览器的原生锚定。

缩放期间继续变换旧位图，替换内容准备好后再提交。同一页的文本节点保持不变，使用 PDF.js TextLayer.update 更新几何尺寸，因此高清重绘不会清除原生文字选区。移除了原先在 selectionchange 中移动 endOfContent 的自定义逻辑：其不可选边界节点会干扰原生跨行拖选。空白页区域仍禁止启动划词，单个中文字允许批注；松手后的选区读取按帧执行，新拖选和卸载会取消旧读取，不再全局清除阅读器以外的选区。笔记覆盖层变化不会重新触发 PDF 栅格化。渲染资源由 `usePdfPageRender` 管理，页面组合与单页交互分别由 `PdfReaderViewer` 和 `PdfPage` 管理。

笔记持久化返回成功或失败，编辑器保存中防止重复提交，失败保留当前草稿供重试，成功才关闭。Cmd/Ctrl+Enter 支持快捷保存，并避开输入法组合输入。旧保存完成时只关闭对应编辑对象，不影响后来打开的其他编辑器。持久化仍按论文串行执行，撤销与论文切换规则不变；草稿保留不等于跨关闭或跨重启自动恢复。

pnpm --dir apps/desktop type-check

pnpm --dir apps/desktop test

2026-10-13：桌面端完整测试 185 个文件、816 项通过，包含阅读器 66 项回归；类型检查通过。lint 无错误，有 25 项既有警告；生产前端构建通过。

真实浏览器对照使用 Chrome、1200×900 CSS 像素视窗、DPR=2，以及本地生成的 24 页文本 PDF，加载生产 PDF.js、阅读组件与导航 hook。基线为 PR 基础版本，实验版本为本次实现。相同流程为加载、鼠标划词、100%→180%→100% 缩放、顺序阅读 24 页并返回第一页。

| 最终保留的完整页面位图 | 24 | 8 |

两组均通过页面尺寸、缩放文本尺寸、鼠标划词及返回第一页检查。新实现额外验证回收后页面高度不变，重访后恢复位图和文本层。资源数量对照是单次观察，不是帧率或内存基准：尚未测量 CPU 时间、进程族峰值内存、冷暖加载时间和帧率，也未替代原生 Tauri/WebKit 及复杂扫描论文验证。

另外使用同一真实 PDF.js 页面验证选择与缩放：先清除已有选区，再分别正向、反向跨行拖选两行；连续发送 100 次 deltaY=-1 的 Ctrl+wheel，页面从 100% 增至约 116.18%，高清图提交后文字节点身份和选区内容不变。在第 15 页分 20 帧发送缩放事件，阅读点纵向偏移约 0.30 CSS 像素；随后工具栏缩放到 180%，中心阅读点偏移约 0.01 CSS 像素。Chrome 无页面错误。数值来自单次自动化检查，不是手势延迟或帧率测量；事件由浏览器自动化发送，尚未验证真实触控板、原生 WebKit、复杂公式与多栏版式。
