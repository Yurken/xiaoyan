# 当前仅启用 DSH

2026-10-22，按用户决定，后续 Agent 工具集成只继续迭代 DSH。Codex、OpenCode、Pi 暂停，保留源码、子模块、版本清单、构建脚本、测试和已有用户数据。

当前停用位置：

- `features/code-harness/shared.ts` 的活动工具列表仅注册 `dsh`；旧工具偏好自动回退到 DSH。
- 设置页整个“代码助手”区块已注释，不再显示选择项；纵横/聚焦两种布局中，其他工具的页面导入与原路由注册均已注释；旧 `/codex`、`/opencode`、`/pi` 地址重定向到 `/code`。
- Rust 入口的其他运行时模块、状态初始化与 IPC 命令注册均已注释；托管安装命令拒绝安装非 DSH 工具。

前序已完成的版本升级保留为冻结基线，不代表继续提供其他工具的产品入口。已有全局安装和私有运行时没有卸载或删除。

恢复其他工具时，需同步恢复活动工具列表、设置卡片、两种布局路由、Rust 模块/状态/IPC 注册及安装策略，再运行对应集成回归；不要只打开一个界面入口。

验证：DSH、设置与路由 7 个前端测试文件共 38 项通过，DSH Rust 15 项通过，完整 `pnpm type-check` 和 `pnpm lint` 通过；真实 macOS 主窗口确认设置区块已移除、侧栏仍为 DSH。

## 0.6.1 直接进入与浮窗配置

进入 `/code` 时使用已保存的配置自动启动 DSH；缺少运行时才提供安装，失败后提供重试，手动停止不会立即自动重启。旧必经启动页的入口已注释，完整页面与原配置测试保留于 `LegacyDshLaunchWorkspace.tsx` 和对应测试中，未删除旧逻辑。

“配置小妍 API”位于运行浮窗。展开后明确提示需要重启，确认后由主 WebView 执行“检查状态 → 停止 → 同步 → 恢复运行”，避免浮窗因停止而销毁时中断重启。重复请求会合并；同步失败仍尝试恢复原运行状态；新浮窗会向主 WebView 请求最近结果。页面仅显示模型和路由，不回显凭据。

本轮最终全量结果见 [0.6.1 发布前检查](releases/0.6.1-preflight.md)。
