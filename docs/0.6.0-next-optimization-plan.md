## 1. 当前剩余缺口（来自实现盘点）

F1（权限引导）与 F3（解读/翻译/对话）已实现；F2、F4、F5 为部分实现。未关闭项可归为四类：

| 类别 | 缺口 | 出处 |
| --- | --- | --- |
| 发布门槛 | 多显示器 / Retina / 缩放人工回归；权限授予/拒绝回归；应用兼容矩阵（Safari/Chrome、Preview、VS Code、Word/Pages、终端） | 状态文档 F2、技术与发布缺口 |
| 窗口体验 | 站位持久化、断屏恢复、面板边界翻转和跨窗口截图协议已有自动化覆盖；仍需真机验证多屏混插与空间切换 | 状态文档 F2、技术与发布缺口 |
| 隐私与安全 | 助手日志/指标抽样与共享 LLM 错误日志加固已完成；仍需隐私评审与 macOS Spike 结论记录 | 状态文档 F5、技术与发布缺口 |
| 可访问性 | 键盘与基础语义属性已有自动化覆盖；仍需 VoiceOver、动态字体和深浅色真机回归 | 状态文档 F5 |
| 采集精度 | 跨 WebView 协调器已能返回负坐标与跨显示器全局 `x/y`；Retina 与混合缩放仍需真机验收 | 状态文档 F2、F4 |

结论：**0.6.0 的下一步首先是收口，不是堆新功能。** 对标新增能力必须排在发布门槛项之后，或与其并行但不阻塞发布。

## 2. 对标豆包等主流桌面助手

豆包桌面版官方公开页当前强调跨软件问答、截图提问、划词搜索/翻译/解释/总结、网页/PDF 翻译和网页总结等能力（核对日期：2026-08-29，[官方桌面版页面](https://www.doubao.com/download/desktop)）。这里对标的是低摩擦触发、上下文采集和结果复用，不照搬其通用浏览器或应用操作边界，也不把竞品入口形态当作小妍的视觉定义。

与小妍现状逐项对照：

| 主流能力 | 小妍现状 | 判断 |
| --- | --- | --- |
| 快捷键唤起面板 | 已有（Option+Space，可配置、冲突处理） | 已对齐 |
| 常驻桌面入口 | 已有（小妍角色本体，非悬浮球/圆形工具按钮，含状态动画） | 已对齐且差异化 |
| 截图提问 | 已有（自有跨显示器选区层 + 视觉模型） | 自动化能力已对齐；待真机多屏验收 |
| 划词即问 | 无自动划词工具条；需先唤起再采集 | **差距最大项**，但需按小妍隐私原则改造（见 §3.2） |
| 截图识字（可复制文本） | 已有“提取文字”，结果进入可编辑预览并提示识别误差 | 已对齐 |
| 直达动作快捷键（一键解读/翻译选区） | 已有 Alt+1/2/3，可录制、冲突重试且默认关闭 | 已对齐，并保留主动触发原则 |
| 面板自由输入 | 已支持无采集上下文直接开启临时对话并保存为正式会话 | 已对齐最低可用形态 |
| 语音输入/通话 | 无 | 候选；与 F14 多模态标准挂钩，需独立评审 |
| 网页总结、打开应用、应用启动器 | 无 | **不借鉴**：超出科研助手定位，且与“不追踪跨应用行为”原则冲突 |

不借鉴项的共同理由：PRD §4.2 明确不做后台持续采集、不做跨应用行为追踪、不做自动回填；小妍的差异化是“懂研究语境 + 来源可追溯沉淀”，不是通用启动器。

## 3. 优化方案（按优先级）

### P0：收口发布门槛（必须先完成）

1. **执行人工回归矩阵**：在真实 macOS 多显示器环境完成 `0.6.0-desktop-assistant-regression.md` 全部“待测”项，逐行记录机器、系统版本、结果与问题链接。
2. **窗口体验真机收口**：桌面小妍站位持久化、断屏迁移、“重置位置”和面板边界翻转均已实现；当前只执行真机多显示器、空间切换和睡眠唤醒回归，并针对实际问题修复。
3. **隐私收口**：日志/埋点载荷脱敏抽样、敏感内容二次确认和 LLM 上游错误日志加固均已完成；当前归档隐私评审与 macOS Spike 结论（写入 `docs/evolution-runs/` 或状态文档附录）。
4. **可访问性收口**：键盘焦点顺序、屏幕阅读器标签（面板与桌面小妍）、动态字体与深浅色走查，结果回填回归矩阵。
5. **匿名本地指标验收**：最小指标集已经实现、默认关闭且不含正文；当前核对开关、清除、聚合和升级兼容性。
6. **截图真机验收**：跨 WebView 协调器和全局 `x/y` 已实现并覆盖负坐标、缩放换算、取消与超时；当前覆盖 Retina、混合缩放和跨屏拖拽真机矩阵。

以上 6 项共同构成 PRD §8.2 的发布门槛；代码侧能力已经基本落地，当前完成定义以真机矩阵、评审归档及针对性缺陷修复为准。

### P1：对标补齐（收口后或与 P0 并行，不阻塞发布）

1. **直达动作快捷键（已完成）**：支持直接解读选区、直接翻译选区和框选截图，默认不注册、设置页可开启与录制；选区只在用户按键时读取。保存与重试已全局串行化，进行中锁定所有动作行，避免跨行并发响应覆盖状态。
2. **截图识字动作（已完成）**：OCR 结果进入可编辑预览，可复制或继续解读/翻译/对话，并固定提示“识别可能有误”。
3. **面板自由输入（已完成）**：空上下文可直接开启临时对话，有上下文时作为追问；支持保存到正式会话，不含应用启动和网页搜索。

### P2：体验增强（需独立评审，建议进入 0.6.1+ 规划）

1. **语音输入**：面板对话支持语音转文字输入。涉及麦克风权限与新的隐私面，需补权限说明文案与 Spike；可作为 F14（企业赛题五）多模态条款的落点之一。
2. **可配置研究动作模板**：用户自定义“解读/翻译”提示模板并绑定快捷键，即 PRD §8.1 中 0.7.0 候选的“快捷指令/研究动作模板”。
3. **表格/公式截图专项**：视觉模型结果中表格转 Markdown、公式转 LaTeX，与论文精读能力（F05）联动。

### 明确不做（与 PRD 非目标一致）

- 不监听全局选区自动弹出工具条（豆包式划词）：需要轮询辅助功能树或全局事件，违反 PRD §11 与隐私定位。以 P1-1 的直达快捷键替代。
- 不做应用启动器、网页浏览与网页总结：超出科研助手边界。
- 不做结果自动回填第三方应用：PRD §4.2 明确排除。
- 不做后台连续截图/屏幕共享对话：PRD §1 明确排除。

## 4. 验收与节奏

- 每项 P0 对应回归矩阵的具体行或自动化测试，勾选标准沿用“不以代码存在代替人工验收”。
- P1 各项按 `competition-aligned-capability-plan.md` §0.3 维护 3–5 个固定场景（正常、边界、失败/降级、修正），L2 场景通过后方可标记完成。
- 结构性修改遵守 `development-principles.md`：新逻辑进 `features/desktop-assistant/` 的 hook 与组件，不进页面 JSX；完成后跑相关包 `type-check`，跨工作区修改补 `pnpm type-check` 与 `pnpm lint`。

## 5. 建议执行顺序

1. P0-1/P0-2/P0-6 合并执行真实设备回归：多显示器、Retina/混合缩放、空间切换和睡眠唤醒。
2. P0-3/P0-4/P0-5 完成评审归档与人工验收：隐私、权限、VoiceOver、动态字体、深浅色和指标清除。
3. P1 已完成，0.6.0 不再增加同类能力；只修复 P0 回归发现的问题。
4. P2 单独立项评审，与本分支解耦。
