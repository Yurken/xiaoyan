## 1. 当前剩余缺口（来自实现盘点）

F1（权限引导）与 F3（解读/翻译/对话）已实现；F2、F4、F5 为部分实现。未关闭项可归为四类：

| 类别 | 缺口 | 出处 |
| --- | --- | --- |
| 发布门槛 | 多显示器 / Retina / 缩放人工回归；权限授予/拒绝回归；应用兼容矩阵（Safari/Chrome、Preview、VS Code、Word/Pages、终端） | 状态文档 F2、技术与发布缺口 |
| 窗口体验 | 桌面小妍站位按“显示器+边缘+偏移”持久化并安全恢复；动作面板按所在显示器定位并在屏幕边界翻转展开方向 | 状态文档 技术与发布缺口 |
| 隐私与安全 | 日志与埋点载荷自动化脱敏抽样测试；隐私评审与 macOS Spike 结论记录 | 状态文档 F5、技术与发布缺口 |
| 可访问性与度量 | 键盘焦点顺序、屏幕阅读器标签、动态字体、深浅色回归；匿名本地指标（触发、来源、耗时、动作、结果状态、复制/导入） | 状态文档 F5、技术与发布缺口 |
| 采集精度 | 系统交互式截图尚不能返回跨显示器全局 `x/y` 坐标 | 状态文档 F4 |

结论：**0.6.0 的下一步首先是收口，不是堆新功能。** 对标新增能力必须排在发布门槛项之后，或与其并行但不阻塞发布。

## 2. 对标豆包等主流桌面助手

豆包桌面版的主流能力（公开资料）：`Alt+Space` AI 启动器（自由输入、AI 搜索、打开应用）、AI 划词（选中文字自动弹出工具条：搜索/翻译/解释/朗读）、截图提问 `Shift+Alt+A`、截图识字（OCR 提取文本）、常驻悬浮球、侧边栏、语音通话、网页总结/翻译。夸克等产品的桌面形态与之高度重合。

与小妍现状逐项对照：

| 主流能力 | 小妍现状 | 判断 |
| --- | --- | --- |
| 快捷键唤起面板 | 已有（Option+Space，可配置、冲突处理） | 已对齐 |
| 常驻桌面入口 | 已有（桌面小妍角色，非悬浮球，含状态动画） | 已对齐且差异化 |
| 截图提问 | 已有（交互式区域截图 + 视觉模型） | 已对齐；差跨屏全局坐标 |
| 划词即问 | 无自动划词工具条；需先唤起再采集 | **差距最大项**，但需按小妍隐私原则改造（见 §3.2） |
| 截图识字（可复制文本） | 截图走视觉模型，结果不可直接提取纯文本 | 可借鉴，成本低 |
| 直达动作快捷键（一键解读/翻译选区） | PRD §16.2 已预留但未注册 | 可借鉴，直接对标豆包 `Alt+1/Alt+2` 效率 |
| AI 启动器自由输入 | 面板以采集上下文为中心 | 部分差距；先核实面板是否已支持无上下文直接提问 |
| 语音输入/通话 | 无 | 候选；与 F14 多模态标准挂钩，需独立评审 |
| 网页总结、打开应用、应用启动器 | 无 | **不借鉴**：超出科研助手定位，且与“不追踪跨应用行为”原则冲突 |

不借鉴项的共同理由：PRD §4.2 明确不做后台持续采集、不做跨应用行为追踪、不做自动回填；小妍的差异化是“懂研究语境 + 来源可追溯沉淀”，不是通用启动器。

## 3. 优化方案（按优先级）

### P0：收口发布门槛（必须先完成）

1. **执行人工回归矩阵**：在真实 macOS 多显示器环境完成 `0.6.0-desktop-assistant-regression.md` 全部“待测”项，逐行记录机器、系统版本、结果与问题链接。
2. **窗口体验收口**：实现桌面小妍站位按“显示器+边缘+偏移”持久化、断屏迁移与“重置位置”；动作面板按触发显示器定位、边界自动翻转。补对应单元测试（坐标换算、迁移逻辑）与回归矩阵勾选。
3. **隐私收口**：补日志/埋点载荷脱敏抽样自动化测试；归档隐私评审与 macOS Spike 结论（写入 `docs/evolution-runs/` 或状态文档附录）。
4. **可访问性收口**：键盘焦点顺序、屏幕阅读器标签（面板与桌面小妍）、动态字体与深浅色走查，结果回填回归矩阵。
5. **匿名本地指标**：落地 PRD §4.3 的最小指标集（动作类别、耗时、结果状态、来源类型），不含正文；为 KR 评估提供数据基础。
6. **截图全局坐标**：用自有跨屏选区层补齐 `x/y`，覆盖 Retina 与负坐标屏幕（回归矩阵已有对应行）。

以上 6 项即 PRD §8.2 发布门槛的剩余部分，建议作为本分支合入前的完成定义。

### P1：对标补齐（收口后或与 P0 并行，不阻塞发布）

1. **直达动作快捷键**：实现 PRD §16.2 已预留的“直接解读当前选区 / 直接翻译当前选区 / 开始框选截图”快捷键，默认不注册、设置页可开启。选区读取仍在按键瞬间执行一次，符合“用户主动触发”原则。这是对标豆包划词效率的合规路径。
2. **截图识字动作**：截图后新增“提取文字”动作，OCR 结果进入可编辑预览，可复制或转为文本类动作输入；沿用“识别可能有误”标注（PRD §7.2 F3）。复用现有截图会话与脱敏管线，不新增数据面。
3. **面板自由输入**：先核实 `AssistantDock`/面板现状；若尚无无上下文直接提问入口，在面板增加首屏输入框，空上下文时直接开启临时对话，有上下文时作为附加问题。使 `Option+Space` 具备豆包启动器式的最低可用形态（不含应用启动、不含网页搜索）。

### P2：体验增强（需独立评审，建议进入 0.6.1+ 规划）

1. **语音输入**：面板对话支持语音转文字输入。涉及麦克风权限与新的隐私面，需补权限说明文案与 Spike；可作为 F14（企业赛题五）多模态条款的落点之一。
2. **可配置研究动作模板**：用户自定义“解读/翻译”提示模板并绑定快捷键，即 PRD §8.1 中 0.7.0 候选的“快捷指令/研究动作模板”。
3. **表格/公式截图专项**：视觉模型结果中表格转 Markdown、公式转 LaTeX，与论文精读能力（F05）联动。

### 明确不做（与 PRD 非目标一致）

- 不监听全局选区自动弹出工具条（豆包式划词）：需要轮询辅助功能树或全局事件，违反 PRD §11 与隐私定位。以 P1-1 的直达快捷键替代。
- 不做应用启动器、网页浏览与网页总结：超出科研助手边界。
- 不做结果自动回填第三方应用：PRD §4.2 明确排除。
- 不做后台连续截图/屏幕共享对话：PRD §1 明确排除。

## 4. 验收与节奏

- 每项 P0 对应回归矩阵的具体行或自动化测试，勾选标准沿用“不以代码存在代替人工验收”。
- P1 各项按 `competition-aligned-capability-plan.md` §0.3 维护 3–5 个固定场景（正常、边界、失败/降级、修正），L2 场景通过后方可标记完成。
- 结构性修改遵守 `development-principles.md`：新逻辑进 `features/desktop-assistant/` 的 hook 与组件，不进页面 JSX；完成后跑相关包 `type-check`，跨工作区修改补 `pnpm type-check` 与 `pnpm lint`。

## 5. 建议执行顺序

1. P0-1 → P0-2 → P0-6（真实设备回归与窗口/截图坐标互为依赖，先做）。
2. P0-3 → P0-4 → P0-5（安全与度量收口，可与 1 并行）。
3. 全部 P0 完成后合入并灰度；P1-1、P1-2、P1-3 按反馈排入 0.6.0 补丁或 0.6.1。
4. P2 单独立项评审，与本分支解耦。

## 6. 实施进展（2026-08-26，分支 feat/0.6.0-assistant）

已由多个子 agent 并行实现并通过验证（`pnpm type-check`、`pnpm lint`、desktop-assistant 161 个前端测试、93 个 Rust 测试全绿）：

- 已完成：P0-2（站位持久化 + 面板定位翻转）、P0-3（脱敏抽样测试，未发现实际泄漏）、P0-4（a11y 语义属性补齐）、P0-5（匿名本地指标，默认关闭）、P0-6（自有跨屏选区层返回全局坐标）、P1-1（直达快捷键 Alt+1/2/3，默认不注册）、P1-2（截图识字）、P1-3（面板自由输入，原核实为不支持，已新实现）。
- 仍待人工：P0-1 真机回归矩阵全部条目（多显示器/混插缩放、权限授予拒绝、应用兼容、VoiceOver、动态字体与深浅色）；隐私评审与 macOS Spike 结论归档。
- 待评审疑点：`apps/desktop/src-tauri/src/llm/transport.rs` 会把 LLM 供应商错误响应体预览写入诊断日志，某些网关可能在错误中回显 prompt 正文，建议统一脱敏策略（共享 LLM 基础设施，非助手域，本次未动）。
- 已知小缺口：自由会话结果页的导入按钮在无捕获内容时无响应（既有守卫未动）；直达动作在预览开启时已有“确认后将直接执行”标识，但事件总线链路需真机端到端验证。
