- 日期：2026-09-11
- 状态：已完成；仅在本次受约束切片中采纳，继续观察执行稳定性
- 分支：`codex/grok-060-next`，基于 `feat/0.6.0-assistant@ce3e88bc`
- 候选工具：Grok Build CLI `1.0.13`（构建 `5e9a58528b76`）
- 候选模型：请求 `grok-4.6`，服务端实际指纹 `grok-4.6-build`
- 角色分工：Grok 负责受约束的代码审查与实现；Codex 负责架构边界、复现、代码审查与验收
- 工作区基线：新建独立 worktree，开始时除本文外无业务代码改动
- 评测数据：`XCG-core-agent-gates` v1；0.6.0 桌面助手发布回归矩阵；下述冻结代码审查任务
- 对照：`feat/0.6.0-assistant@ce3e88bc` 的既有实现和自动化结果

## 主假设

如果让 Grok 4.6 在明确的发布边界内审查桌面助手最近的状态机、权限和隐私变更，那么它能发现并修复一个可复现的 0.6.0 发布缺陷，同时保持结构、隐私与核心 Agent 门禁不退化。

若没有可复现缺陷，或改动只增加功能、扩大权限、伪造真机验收、破坏结构边界，则本轮不采纳 Grok 为该切片主程，不为模型测试制造空改动。

## 冻结任务

第一阶段只读审查，不修改文件。范围限定为：

- 直达快捷键触发到采集、确认和动作执行的状态边界；
- 跨显示器截图请求的开始、取消、超时和旧请求隔离；
- 权限拒绝后的剪贴板、手动粘贴和文件候选降级；
- 临时捕获内容、窗口标题、日志、指标与正式资产之间的隐私边界。

Grok 必须输出至多 3 个发现。每个发现包含严重级别、具体文件与行号、可复现触发条件、用户影响、代码证据、最小修复和回归测试。缺少可执行证据的猜测不得列为缺陷；不得把人工回归矩阵中的“待测”改成“通过”。

第二阶段只处理经 Codex 独立复现的最高优先级发现。实现须满足：

- 不增加 0.6.0 新功能，不扩大默认采集或自动执行权限；
- 页面保持组合职责；状态与副作用进入现有 hook/service；
- 若触达超过规模上限的大文件，先抽离本次触达逻辑；
- 补充能复现缺陷并证明修复的必要测试；
- 不写入研究正文、截图正文、窗口标题、凭据或上游错误正文到日志/指标；
- 不修改与本切片无关的用户改动、依赖版本或 vendored 源码。

## 通过门槛

1. Codex 可从代码或自动化测试独立复现 Grok 的缺陷判断；
2. 修复前测试失败、修复后通过，或提供等价的确定性证据；
3. Desktop 助手相关前端测试、Rust 相关测试和 Desktop `type-check` 通过；
4. `XCG-core-agent-gates` v1 不退化；
5. 仓库级 `pnpm type-check` 与 `pnpm lint` 通过；
6. `cargo fmt --check`、`git diff --check` 通过；
7. Codex 架构审查没有未解决的 P0/P1 问题。

## 运行结果

- 会话与身份：通过 Grok Build CLI 的 xAI device auth 登录；用户在发送本分支的桌面助手代码、测试和规划文档前明确授权。
- 实际模型：CLI 请求 `grok-4.6`，成功会话的 usage 返回 `grok-4.6-build`。
- 审查稳定性：两次较大范围审查分别超过 5 分钟和 3 分钟未完成；缩至单个 hook 后约 30 秒完成。输出没有遵守约定 JSON，严重级别写成 `medium`，需由 Codex 重新归类。
- 实现稳定性：受限于 3 个文件和 `read_file/grep/search_replace` 的实现会话在约 2 分 40 秒达到最大回合，但已经完成有效修改；单条 lint 修正也在完成编辑后达到最大回合。主实现会话约使用 198,732 tokens、费用约 0.04545 美元，效率低于本切片需要。

## 经独立复现的发现

设置页只让当前直达快捷键行显示保存状态，其他行仍可操作；hook 又只维护一个 `savingAction`。用户快速操作不同行时会并发调用保存或重试，较早完成的请求可提前清除忙碌状态，失败后的全量回读还可能覆盖较新的状态。

Codex 从组件禁用条件、hook 的单一状态字段和异步 `finally` 路径独立确认该竞争条件，将其归类为 P2。其余宽范围审查没有形成可验收输出，不能据此宣称没有其他缺陷。

## 代码与测试

- `useAssistantDirectShortcuts` 通过同步 ref 在 React 状态提交前拒绝重叠 mutation，并将保存和重试统一到一个串行执行器；失败后仍保留原有全量状态恢复。
- 设置组件在任一 mutation 期间禁用所有行的开关、录制输入、应用和重试控件，仅当前行显示加载动画。
- 新增 hook 级确定性并发测试，证明重叠保存/重试不会产生第二次 Tauri invoke；新增组件测试，证明其他行同步锁定且当前行的加载反馈正确。
- Grok 新增测试后产生 1 条非空断言 lint 警告；第二次窄任务用显式守卫修正，最终未增加 lint 警告。

- 修改前：Desktop 助手 44 个文件、175 项测试通过；Desktop `type-check` 通过；核心门禁均分 2.5、硬失败 0、未知硬失败 0。
- 修改后：Desktop 全量 146 个文件、567 项测试通过；目标测试 14 项通过；仓库级 `pnpm type-check` 通过；`pnpm lint` 为 0 error、18 条分支既有 warning；核心门禁均分 2.5、硬失败 0、未知硬失败 0，成对非退化门禁通过；`git diff --check` 通过。
- Rust 相关助手子集修改前 90 项通过，本轮没有修改 Rust。`cargo fmt --check` 仍被基线中未格式化的既有 Rust 文件阻断；其输出不涉及本轮 3 个 TypeScript 文件，因此不把它写成通过，也不扩大本轮去清理无关格式差异。
- 人工验收：未执行真实 macOS 多显示器、系统权限、目标应用和 VoiceOver 矩阵，状态保持待测。

## 决策

采纳本次串行化修复，并允许 Grok 在明确文件边界、短任务和 Codex 架构复核下担任该切片主程。暂不把 Grok 设为仓库默认主程：较大审查无法稳定完成，成功实现也两次以最大回合退出，且成本明显偏高。下一步仍按 0.6.0 发布计划执行真实 macOS 回归，只修复矩阵发现的问题。
