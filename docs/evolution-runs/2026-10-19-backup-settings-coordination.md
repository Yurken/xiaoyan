# 备份恢复与设置保存协调（2026-10-19）

## 问题与行为
设置页原先直接调用整库备份恢复，再读取缓存并替换表单，没有进入设置保存队列。在途保存、尚未触发的防抖保存及卸载补写可能覆盖恢复值。原生拒绝也不能证明恢复未提交，而 settings_get 仅读取内存缓存。

本切片让确认恢复同步预占 settings replacement，清除待保存快照，并按同一窗口的队列等待已有保存结束后执行恢复。成功后通过新命令 settings_reload 从 SQLite 读取全部原始设置，合并默认值、同步缓存并返回既有脱敏字段，再接纳表单。settings_get 的既有缓存读取行为不变。

所有备份恢复拒绝都保守保持保护，错误提示区分“备份已恢复但读取失败”与“恢复结果尚未确认”。重新读取仅执行 settings_reload，不重复恢复；读取失败时不会保存旧表单。原生错误仍是字符串，本切片不通过匹配文案推断提交状态。即使是错误密码等写前拒绝，也需要先重新读取，丢弃未保存的旧表单草稿后才能继续操作。

## 页面生命周期与反馈
- 未完成的权威读取保留在模块级协调器中。新挂载等待已排队操作；如存在未恢复状态，优先读取数据库。读取失败显示加载错误并阻止设置编辑、历史配置操作及备份入口，可在原页点击“重新读取”。
- 初始读取排队时记录恢复版本；后来预占的恢复不能借用较早的读取提前解除保护。读取过程中若版本变化，等待后续恢复并重新读取。
- 恢复失败后密码弹窗可关闭，但不能重复提交；读取成功按原弹窗的版本与挂载身份关闭，迟到回调不会关闭新弹窗。
- 历史记录初次加载等待已有保存/恢复任务。显式历史刷新不反向等待正在通知它的队列，避免循环等待。
- 核心读取和接纳先完成，历史刷新、应用锁通知的错误独立处理；通知不会把成功恢复标成失败。应用锁通知失败仍会完成弹窗回调。
- 配置文件导入继续使用原有 settings_get 与错误处理语义；没有修改云端同步恢复入口。

## 范围与限制
协调器覆盖同一 JavaScript 窗口的设置页自动保存和本地备份恢复，不是跨窗口或所有原生写入口的全局互斥。数据库查询与缓存发布也不构成跨写入口事务。附件仍可能在 SQL 提交前写入；本切片不提供整个备份恢复的文件原子性。现有整文件读取和 Base64 内存峰值没有改变。
