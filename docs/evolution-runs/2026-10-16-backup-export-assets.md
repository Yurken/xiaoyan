## 问题与范围

旧 `settings_service::collect_file_asset` 在非空文件路径读取失败时直接返回，调用方无法获知遗漏。导出仍序列化并加密返回；恢复遇到缺少资产的条目时保留原路径，换机器后可能留下无法打开的文件引用。上述结论来自源码控制流，不是运行复现。

现有页面说明只包含可读取的文件，但没有指出本次实际遗漏了哪些已关联附件。此切片选择在读取失败时取消整个导出，避免返回一份悄悄遗漏已关联文件的备份。空路径、NULL、缺少路径仍表示没有本地文件，允许导出。

## 实现

- 按大文件先抽离原则，将导出附件收集及路径命名移入 `settings_backup_export_assets.rs`；恢复逻辑保留原处。
- `collect_file_asset`、`collect_row_assets` 返回 `Result<(), String>`，并在 `export_all_data` 使用 `?` 传播错误。失败发生在载荷序列化和加密前，调用者收不到可保存的备份字符串。
- 错误包括表名、记录 ID、文件路径、系统读取原因和修复引用的提示，不包含文件正文。
- 三种资产来源仍为 `papers`、`paper_figures`、`experiment_attachments`；保留内部相对路径、外部回退路径和按原始路径去重。已经捕获的文件不重复读取，即使之后源文件变化或消失。
- 新增备份专用说明，出现在设置卡片和密码弹窗。同步页面继续使用原有说明，独立的 sync_service 快照路径没有改动。仍注册的 webdav_upload_backup 同样调用 export_all_data，因此也会在附件读取失败时于上传前返回错误；这是同一备份导出契约的保护。
- 前端沿用 `useDataBackup` 的异常处理：显示原生错误、保留弹窗并结束忙碌状态；原生导出拒绝后，不打开保存对话框、不写备份、不记录导出成功。

没有改变 version 1 备份结构、加密协议、导入兼容性、数据库表清单或依赖。没有新增并行读取。文件仍整份读入并编码，尚未降低正常大备份的内存峰值，也未解决跨表读取快照一致性、回退文件名碰撞或恢复写文件早于 SQL 提交的问题。本切片不保证备份包含范围外的数据。
