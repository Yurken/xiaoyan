# 小妍下一阶段发展建议

日期：2026-09-11。审阅基线：本地提交 `47523da8`，版本 `0.5.5`。

本文是发展建议，不变更已批准的版本范围。结论来自仓库文档与关键代码抽查，以及外部产品官方资料；未运行应用、用户访谈或真实模型任务，不能据此宣称功能已通过验收。

## 核心判断

建议围绕「可续接、可核验、能沉淀成果的个人科研工作台」投入下一阶段。先验证用户隔几天回来能否少解释背景、继续推进一个研究问题，再扩展跨应用入口和代码成果回流。

优先验证的人群是假设中的研究生与个人研究者：已有一批论文、持续围绕一个课题阅读与写作、经常中断后返回。当前没有留存、活跃用户结构和付费证据，因此这是待验证的目标人群，并非已确认的市场结论。

## 按结果排序的路线图

时间窗从立项开始计算，只表示顺序和范围建议，不是开发工期承诺。每轮保持一个主假设、一个端到端切片、最多两个辅助工程项。

| 顺序与窗口 | 用户结果 | 建议交付切片 | 验证指标与决策门槛 |
| --- | --- | --- | --- |
| P0：先用约 2 周建立基线 | 隔几天返回课题，能直接进入下一步 | 5 组「空白会话 vs checkpoint」配对任务；核对旧目标与当前资产；把失败归入上下文、证据、交互或工具类别 | 记录重复说明量、得到首个可用结果的时间、有效续接率；若多数任务没有改善或用户不愿续接，暂停扩展续接自动化 |
| P1：首个产品迭代 | 继续研究后，得到一份可保存、可检查的成果 | 选定「继续课题 → 精读已有论文 → 补全证据笔记 → 保存 → 下次续接」；处理一个最常见的上下文错误或中断问题 | 同一批配对任务中，建议以重复说明量中位数减少 30% 作为初始目标；无证据错配或资产丢失。该阈值是提议，需在基线后校准 |
| P1：后续质量迭代 | 用户能核对关键结论，也能纠正旧知识 | 从一个精读/综述场景起步，让关键主张关联原文位置，区分论文事实、用户判断与模型推断；来源修正时提示受影响结论 | 同时检查证据能否打开、是否实际支持主张；固定场景的关键主张逐条核验，记录人工纠错量与证据覆盖率 |
| P2：上述结果获得支持后 | 在常用外部应用中收集材料并回到同一研究主题 | 悬浮助手先核对实现状态，再做 macOS 文本切片：快捷键 → 显式提供文本 → 预览 → 解读/翻译 → 保存至研究主题 | 看有效成果保存与后续使用，而非悬浮球点击；验证前台应用切换、权限拒绝和降级。截图、多屏与其他平台按实际结果排期 |
| P2：按真实需求推进 | 代码工作能够反过来推动研究判断 | 选一个现有 Harness，建立「研究任务 → 工作目录/会话 → 结果文件与运行信息 → 用户确认 → 证据资产 → 下一轮计划」 | 用 3 个小型复现实验验证结果可定位、运行条件可说明、失败状态可保留、下一步可执行；通过后再推广到其他 Harness |

北极星指标沿用现有总纲的「有效续接率」：主动续接后，无需重输已保存背景、引用正确主题或资产、接受下一步或保存可用成果，并且没有因错误上下文重开任务。

首次产出时间、任务完成率和每周有效研究任务数作为补充，帮助识别续接以外的瓶颈。成本与延时按同类任务比较；事件优先保存在本地，不采集研究正文作为分析数据。小样本用于决定下一步实验，不用于宣称总体提升。

## 产品与工程取舍

1. **把研究主题做成统一工作入口。** 用户从课题看到当前目标、已确认结论、待核对证据和下一步；论文、写作、知识与代码模块继续作为专门工作区。
2. **让证据连接已有资产。** 优先补当前任务需要的来源、版本与纠错传播，不先做一个更复杂但缺乏使用验证的图谱界面。已有假设卡和规划转换也应复用。
3. **让四套 Harness 服务于科研成果。** 近期维护兼容性与稳定性，优先验证一个成果回流适配器；不以增加第五种引擎作为核心里程碑。
4. **降低接入现有科研习惯的成本。** 先盘点已有 BibTeX 支持，再根据访谈中的迁移阻力决定 Zotero/标准格式导入导出的具体缺口。Zotero 已提供文字处理器集成，Elicit 已提供论文研究与带引用报告；据此推断，小妍值得验证的定位是长期研究状态与本地资产连续性，而非依靠单一摘要或引用功能。
5. **工程投入跟随主切片。** 补模型/策略版本、耗时、失败分类和结构化反馈，使每次变化能比较；触达大文件时先拆相关逻辑，遵守 `features/<domain>/`、hook 与 service 边界。模型或关键代理升级继续执行固定评测和能力差异记录要求。

## 暂缓的投入

- Web/Mobile 全量功能对齐；继续以 Desktop 为旗舰端。
- 同时扩张专利、格式工具、领域看板等多条独立主线。
- 没有使用证据前建设大规模远程埋点、复杂团队权限或完整商业化体系。
- 为模型升级而重写运行时，或在缺少回放证据时扩大自主执行权限。

如果真实用户表现出更强的单次检索或精读需求，应把优先级转向该场景的首次产出与证据质量，而不是强行维持续接主线。收费与团队协作的方向应在重复使用价值成立后另做验证。

## 第一轮具体工作

主假设：现有 checkpoint 可以减少用户恢复课题状态的成本。

- 准备 5 组有中断背景的研究任务，交叉安排空白会话和 checkpoint 的测试顺序，避免重复做同一题产生学习偏差。
- 使用相同模型配置与同版本资产，记录重复说明量、首个可用成果耗时、证据错误、保存结果与是否愿意再次使用。
- 从失败记录选择一个最高频问题，完成一个小切片并配对回放；若主假设不成立，停止扩大实现。
- 两个辅助项：核对路线图与当前代码的状态差异；补最小运行元数据。无需先搭建完整分析平台。
