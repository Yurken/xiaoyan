# 笔记工作区重构：产品需求与架构设计

状态：阶段 B 已开始实施。日期：2026-09-13。

## 1. 概述

把目前分散的知识卡片列表、全屏编辑页和论文笔记弹窗，重构为统一的笔记工作区。核心体验是：找到一篇笔记，在原位阅读和修改，明确知道内容是否保存，下次回来继续。

本轮以 Desktop 为首发端，保留 Markdown、现有笔记 ID、研究主题和证据关联。视觉必须遵循小妍现有的新拟态体系，此项已由用户明确指定。交付重点依次是数据可靠、阅读与编辑连续、检索准确；可视化编辑需要通过旧内容兼容性验证后才能成为默认。

## 3. 背景与现状

用户反馈：笔记展示、编辑等基础功能可用性差，需要重新设计。以下结论来自当前源码审查，尚未进行真实用户访谈、运行态复现或性能测量；代码风险与已复现缺陷分开记录。

| 现状证据 | 用户影响 / 风险 | 设计回应 |
| --- | --- | --- |
| `NoteReader.tsx` 默认 `split`，`MarkdownSplitEditor.tsx` 是 textarea + 预览 | 阅读先看到源码；窄窗中两栏挤占正文 | 已有笔记默认阅读；编辑、源码和可选分屏在同一正文区切换 |
| `NoteCard.tsx` 的查看和编辑都导航至 `/notes/:id`；`NoteReader.tsx` 返回固定 `/knowledge` | 连续查看多篇笔记需来回跳转；研究主题上下文难保留 | 列表与正文同屏；URL 和视图状态保留上下文 |
| `NoteReader.tsx` 用路由 state 初始化笔记，缺省时加载全部笔记再查 ID | 快照可能过时；直接打开一篇需读取全库正文；ID 切换时状态隔离需补验证 | 按 ID 加载，路由快照只做占位；会话按 noteId 隔离 |
| `NoteReader.tsx` 无草稿持久化、离开保护或自动保存；保存完成直接清 dirty | 存在离开丢稿、保存期间继续输入却被标成已保存的风险 | 持久草稿、编辑序号、串行保存、离开与关闭保护 |
| `NoteEditorModal.tsx` 对脏草稿的 Esc/遮罩关闭静默拦截，且标题正文均必填 | 不同入口的创建与关闭行为不一致 | 空标题允许自动命名；关闭时提供明确的保留/处理选择 |
| 前端 update 与 move 分两次调用；Rust update 分字段执行 SQL，无统一事务 | 标题、正文、主题可能只保存一部分 | 一个 patch，一个事务，一个版本 |
| `knowledge_list_notes` 搜索尝试远程 embedding，按 `rag_top_k` 截断；主题在前端再筛选 | 输入检索可能受外部服务延迟影响；主题内结果可能漏召回 | 本地关键词检索为默认；先限定范围再排序分页；语义查找独立入口 |
| `Knowledge.tsx` 从图谱 snapshot 提取 notes，首选视图默认 graph | 阅读笔记依赖大范围图谱加载；笔记入口不够直接 | 笔记查询独立于图谱；图谱关联按需加载 |
| 列表默认卡片，list 模式仍用 NoteCard；主要展示 created_at | 密度切换有限，最近修改的内容不突出 | 列表仅展示标题，按置顶与最近修改排序 |
| `PaperNoteViewerModal.tsx` 直接渲染内容；主编辑器有本地附件 URI 解析 | 同一篇导入笔记跨入口的图片表现可能不同 | 统一正文渲染和附件解析入口 |
| Rust 删除直接 `DELETE`；分组删除调用研究主题删除接口 | 误删难恢复；笔记视图操作的影响范围过大 | 笔记回收站；主题删除只在主题管理中进行 |

## 4. 目标与验收指标

目标：用户能把阅读材料和研究思考沉淀成可持续编辑、可查找、可追溯的个人研究资产。

以下数字是本次设计的建议验收门槛，不是现状测量结果。阶段 A 固定设备、数据集和测试步骤后校准，版本发布前记录实际结果。

| 结果 | 建议门槛 | 验证方式 |
| --- | --- | --- |
| 连续查看笔记 | 列表中单击一次显示正文；切换不离开工作区 | 同一主题连续阅读 5 篇再返回，筛选、位置不丢 |
| 开始书写 | 点击新建后直接输入正文，无必填弹窗 | 至少 5 位目标用户中 4 位无需指导完成 |
| 基础任务成功率 | 找到笔记→修改→重开核对，5 位用户至少 4 位独立完成 | 与旧版执行同一套任务，记录耗时与误操作 |
| 保存可信 | 所有已确认持久化的内容在故障恢复后保留；旧响应不清除新输入 | 延迟、失败、乱序、关闭、重启、多窗口冲突测试 |
| 本地响应 | 1 万条笔记下，关键词检索 P95 ≤300ms；选中到首屏正文 P95 ≤300ms | 固定硬件，分别报告冷/热路径；不含远程语义搜索 |
| 编辑流畅 | 5 万字含表格/公式的样本，输入到绘制 P95 ≤50ms | 中文输入法、连续输入、粘贴、撤销和长文滚动 |
| 内容兼容 | 全部固定样本无文字、引用和附件丢失；只读打开不改写原文 | Markdown 往返测试、导出比对和人工视觉检查 |

## 5. 用户与场景

1. **阅读与摘录**：从论文打开研究笔记，查看原始证据，补充自己的理解，然后回到原论文。
2. **持续研究**：回到某个主题，找到最近修改的实验或方法笔记，继续未完成的部分。
3. **整理资料**：把网页、导入文件、对话产物归入主题，修改标题和标签，批量导出。

工作假设：用户更常连续读写少数笔记，而非浏览大量卡片；该判断需用试用验证。知识笔记 `KnowledgeNote` 与 PDF 页内批注 `PaperNote` 是不同实体：前者承载长文，后者承载页码、矩形高亮和批注。统一术语、跳转和引用体验，保留两种数据模型。

## 6. 价值与范围取舍

- **找得到**：主题、来源、标签与关键词在同一范围内组合；默认最近修改排序，列表仅显示标题，命中内容在打开正文后定位。
- **读得下去**：正文占据主要空间，标题、段落、表格、代码、公式与引用清晰；来源详情按需打开。
- **改得顺手**：原位进入编辑，常用格式可用工具栏；源码模式保留完整表达能力。
- **存得放心**：自动保存、草稿恢复、冲突提示、可恢复删除；保存状态可解释。
- **回得去**：论文/网页/对话来源可跳转，缺失来源有明确状态；论文页码引用定位回阅读器。

本轮不扩展无限层级文件夹、块数据库、多人实时协作、双链图谱或 AI 改写平台。已有图谱和生成笔记能力保留入口；图谱不是浏览笔记的加载前提。暂无竞品对比数据，不宣称优于任何竞品。

## 7. 方案

### 7.1 信息架构与工作区

产品用词统一为「笔记」；来源使用「手动记录 / 论文分析 / 网页剪藏 / 文件导入 / 对话 / 综述」，主题使用「研究主题」，不把主题再称作文件夹。

```text
小妍应用导航（复用现有外壳，不增加另一套全局导航）
┌─────────────┬──────────────────────┬───────────────────────────────────┐
│ 笔记导航     │ 搜索当前范围    新建  │ 主题 / 笔记      已保存  编辑  详情 │
│ 全部笔记     ├──────────────────────┤                                   │
│ 最近打开     │ 笔记标题一             │ 大标题                             │
│ 置顶         │ 笔记标题二             │ 来源与更新时间                     │
│ 未归档       │ 笔记标题三             │                                   │
│ 回收站       ├──────────────────────┤ 正文：段落、表格、公式、图片、引用    │
│             │ 选中的笔记保持高亮     │                                   │
│ 研究主题     │                      │                                   │
│  标签筛选    │                      │ 可展开：目录 / 来源 / 标签 / 关联   │
└─────────────┴──────────────────────┴───────────────────────────────────┘
```

- 笔记导航建议 180–220px，标题列表 240–280px，正文理想行宽 680–800px。断点依据扣除应用侧栏后的可用宽度测量。
- 可用宽度 ≥1200px 时导航、列表、正文同屏，足够空间时详情侧栏展开；900–1199px 收起笔记导航为范围选择器，详情为抽屉；<900px 在列表和正文之间单页切换，显示明确返回列表按钮。
- 正文支持专注模式，收起辅助区；列表位置、文档阅读位置和当前范围独立记忆。长表格与代码块局部横向滚动，不挤压正文。
- **笔记列表仅展示标题，已由用户明确指定**：不展示摘要、来源、时间、标签或置顶图标；标题较长时自然换行，保留新拟态内凹选中态。来源、时间和标签在正文头部或详情中查看。搜索结果也仅展示标题，打开后在正文定位命中处；搜索仍覆盖正文和标签。取消摘要/卡片密度切换，旧视图偏好统一迁移为标题列表。
- 主入口落到笔记；知识图谱保留在知识库的相邻视图。已有用户保留上次选择，直接进入笔记的链接不经过图谱。
- 无选中项时优先恢复该范围内上次打开的有效笔记，否则选择第一篇；空列表显示新建入口。筛选隐藏当前笔记时，保留正在编辑的正文并提示「当前笔记不在筛选结果中」，不自动替换草稿。

### 7.2 阅读、编辑和归档流程

| 场景 | 交互规定 |
| --- | --- |
| 打开已有笔记 | 默认阅读；正文和标题只读。点击「编辑」或正文聚焦时的 Cmd/Ctrl+E 原位进入编辑；快捷键冲突需在集成时验证 |
| 新建 | 直接创建本地草稿并聚焦正文，标题可空，首次非空内容取首行短文本为暂定标题；用户改过标题后不再自动覆盖；完全空白离开不制造正式笔记 |
| 编辑 | 单栏可视化 Markdown 为目标默认；工具栏仅标题、粗体、列表、引用、链接及插入菜单。图片、表格、代码、公式收在插入菜单；源码与分屏为进阶选项 |
| 切换模式 | 保留正文、草稿、选择与尽量相近的阅读位置；只读切换不触发保存。格式转换不支持的内容保持原文并引导源码编辑 |
| 保存 | 停止输入约 800ms 后提交，Cmd/Ctrl+S 立即提交；保存不中断输入；输入法组合未结束不重建文档、不改光标 |
| 保存状态 | 「有未保存修改」「草稿已保存在本机」「保存中…」「已保存 14:32」「保存失败，草稿已保留」「有其他修改，需处理」；成功只指本地数据库提交成功，不暗示云同步成功 |
| 离开/关闭 | 草稿已确认持久化时可离开并下次恢复；草稿写入失败则显示「重试 / 导出当前内容 / 留在此页 / 放弃修改」；不使用会消失的 toast 承载唯一错误信息 |
| 主题和标签 | 在详情中编辑；与正文进入同一保存快照，标签不再只对自动生成内容展示；移动后选中笔记保持打开，可跳转新主题 |
| 搜索 | 默认当前范围的本地关键词搜索；标题、正文、标签参与；明确显示范围和结果总数；没有结果时可清除筛选或切到全部笔记 |
| 语义查找 | 用户主动开启，显示加载/失败/结果数量限制；不可阻塞关键词搜索；不能以有限召回结果声称“全库没有” |
| 整理 | 置顶、批量改主题、导出、移入回收站；删除主题在主题管理进行，笔记导航只提供筛选与取消归档 |
| 删除 | 移入回收站，提供撤销和恢复；首版不自动清空；永久删除需单独确认并说明关联证据影响 |
| 来源 | 显示原论文/网页/对话；点击论文引用可回原页；从 PDF 批注提炼笔记保留来源快照及引用，原批注不被替换 |
| AI 生成笔记 | 通过同一写入服务创建，来源可追溯；有人工修改时再次生成默认新建副本，不静默覆盖 |

回收站笔记从普通列表、搜索、RAG、自动 Wiki 编译及导出默认集合排除；原证据链接保留并标记来源不可用。恢复使用原 ID。已有 Wiki 中的相关引用标记待检查，不能让旧内容继续被当成有效笔记来源。

### 7.3 视觉、可访问性和异常状态

- **新拟态是确定的设计约束**：遵循 [.impeccable.md](../.impeccable.md) 与 [theme.css](../apps/desktop/src/styles/theme.css)。本次原型以项目设计上下文指定的浅色为基准，使用浅灰表面、双向柔光阴影和 24–28px 主容器圆角。
- 层级映射：正文主容器使用 `Card raised`，列表容器使用 `Card flat`，搜索、编辑输入和详情槽位使用 `inset/control`。普通列表项保持轻量，选中项呈内凹按压态；不为每行重复叠加悬浮阴影。区域用阴影深度、表面明度及柔和边界区分。
- 操作映射：编辑/完成是正文区域主操作，使用现有 `Button primary`；新建使用 `secondary`；专注、置顶、详情等工具操作使用 `ghost`，激活态使用内凹 token。蓝色只用于关键操作、焦点和必要选中强调。
- 实施时直接复用 `packages/ui` 的 Card/Button 与现有 `--rc-card-*`、`--rc-control-*`、`--rc-chip-*`、`--rc-button-*` token，不在 feature 中复制色值、阴影或创建另一套拟态组件。独立原型使用隔离的主题 token 副本展示；正文保持清晰排版，避免阴影进入每个段落。代码实现保留现有主题 token 的深色和历史 `modern-minimal` 回退行为。
- 次要文字与选中标签也应满足 4.5:1 的文本对比度；不能只靠阴影表达选择和键盘焦点。输入聚焦沿用 `control-focus-shadow`，减少动态效果时禁用按压位移。
- 正文建议 16px、1.7 行高，标题 28–32px；系统字体支持中文。行内公式、代码和引用不能被摘要清洗逻辑影响。
- 图谱计数从卡片主信息降为详情中的「支撑的结论」，减少阅读干扰。
- Tab 可达所有操作，焦点可见，图标按钮有标签；列表区域内方向键选择，编辑器内方向键仍用于编辑。输入状态不被全局快捷键抢占。
- 加载失败、正文不存在、来源失效、图片缺失、保存失败、版本冲突各有独立状态与对应动作。主题列表加载失败不应阻止正文编辑，但禁止用空列表覆盖既有主题值。
- 引用 HTML 与外部链接沿用并验证安全渲染策略；不执行笔记中的脚本。损坏图片保留替代文字和原始引用。

### 7.4 前端模块边界

遵守 [开发原则](development-principles.md)：在现有功能域下新增 `features/knowledge/notes/` 子域，页面只组合；每个 hook 管理一个职责。先抽离当前触达逻辑，不继续扩写现有大文件。

```text

pages/NoteReader.tsx              /notes/:id 兼容入口，组合同一工作区
features/knowledge/notes/
  NotesWorkspace.tsx             组合导航、列表、正文、详情
  NotesNavigation.tsx / NotesList.tsx / NoteTitleRow.tsx
  NoteDocument.tsx / NoteReadView.tsx / NoteDetailsPanel.tsx
  NoteToolbar.tsx / NoteSaveStatus.tsx / NoteConflictModal.tsx
  editor/                       可视化编辑与源码编辑适配器
  useNotesQuery.ts               范围、查询、分页、请求代次、缓存失效
  useNoteSession.ts              按 ID 加载与草稿恢复，选择会话
  useNoteAutosave.ts             编辑序号、串行提交、失败重试与冲突
  useNoteDraftPersistence.ts     持久草稿读写、关闭与恢复
  useNoteAssets.ts               文件导入与附件解析
  useNoteActions.ts              新建、置顶、归档、回收站

```

- `notesShared.ts` 相关纯函数迁入新子域 `shared.ts`，旧路径临时重导出，不复制；`NoteDraft` 从组件文件迁到子域类型。
- `lib/client.ts` 已超千行，先将笔记 Tauri 适配抽入 `lib/knowledgeNotesClient.ts`，保留旧导出兼容；UI 不直接依赖它。
- `NoteEditorModal`/`PaperNoteViewerModal` 变为薄壳，复用文档会话与正文组件；同一文档只挂载一个编辑实例，后续移除重复编辑实现。
- 详情按 ID 查询；路由 state 只允许作初屏提示，后台重验不得覆盖 dirty 草稿。切换 ID 时旧请求响应不得更新新会话。
- 草稿由文档会话唯一持有；查询缓存保留已提交版本，不能把后台刷新值直接重置为编辑内容。
- `note_changed` 事件包含 ID、版本、变更类型；列表、论文入口、图谱按需失效。事件不保证每次都收到，重新聚焦时按版本校验。
- 图谱只订阅笔记变化及按需取关联统计；保存完成后无需等待图谱刷新。
- 通用领域契约进入 `packages/types`，桌面草稿和编辑器状态留在子域。Web 稳定后再同步体验，但本轮涉及共享契约的兼容性必须同时验证。

### 7.5 编辑器与内容协议

**决策：Markdown 继续作为权威正文；可视化模型只是编辑过程的临时结构。** 不把旧文档批量迁成某个编辑器私有 JSON。

可视化编辑优先验证 Milkdown；其官方架构包含 Markdown 与内部文档模型转换、语法插件。源码编辑验证 CodeMirror 6，其状态与事务模型适合保留选择和精确编辑。两者均通过薄适配器接入，不能让编辑器类型扩散到领域层。参考：[Milkdown 架构](https://milkdown.dev/docs/guide/architecture-overview)、[CodeMirror 系统指南](https://codemirror.net/docs/guide/)。这是候选技术判断，不是已经通过小妍兼容性验证的结论。

适配器约定：加载 Markdown、取当前 Markdown、订阅本次编辑、撤销/重做、聚焦、保存/恢复选择、销毁；组件渲染不能每次重建编辑器。可视化和源码模式共享文档会话；切换时保留检查点，明确撤销边界，不能回滚到另一篇笔记。

固定样本至少包含中文输入法、GFM 表格、任务列表、嵌套列表、引用、代码围栏、数学公式、脚注、原始 HTML、引用标记、`xynoteasset://` 图片与 5 万字长文。未编辑时须字节保持；已编辑时允许格式规范化，但文字、链接目标、公式与附件引用语义不能丢失。

未支持语法以保留原文的只读块呈现；不能保证保留的整篇笔记转源码模式，并解释原因。可视化编辑未过门槛，则阶段 B 先发布单栏源码编辑 + 工具栏 + 独立阅读，不能以“支持 Markdown”为理由接受旧内容丢失。

### 7.6 本地内核与数据设计

将 `commands/knowledge_notes.rs` 的存储、副作用与导入逻辑抽到 `services/notes/`；命令保留参数转换。建议拆分 `repository.rs`、`service.rs`、`query.rs`、`drafts.rs`、`assets.rs`、`import.rs`。Rust SQL 与文件系统副作用留在内核，前端通过 hook 调用。

在原表增量增加字段，保留 `id/content/source_type/source_id/research_interest_id`：

| 对象 | 增量字段 / 约束 |
| --- | --- |
| knowledge_notes | `revision INTEGER NOT NULL DEFAULT 1`；`pinned_at`、`deleted_at` 可空；正文仍是 Markdown |
| note_drafts（新，本机私有） | `draft_id`、可空 `note_id`、`window_session_id`、`base_revision`、`edit_seq`、标题/正文/标签/主题快照、写入时间；不同窗口不可共用一行覆盖彼此 |
| note_revisions（新） | `(note_id, revision)` 唯一，保存可恢复内容快照与操作来源；首版保留编辑会话检查点、恢复前版本和删除前版本，不为每个按键建立历史 |
| note_assets（新） | 附件 ID、note_id、相对路径、文件名、MIME、大小、hash；可用现存 URI 延迟建立索引；不改写旧 URI |
| note_mutations（新） | `mutation_id` 唯一、请求摘要、结果版本；提交超时重试返回同一结果，避免重复新建 |

新增契约（名称为建议，落地时与现有 SDK 一致）：

```ts
listNotes(query: { scope; keyword?; tags?; source?; sort; cursor?; limit }): NotePage;
getNote(id: string): NoteDocument;
createNote({ mutationId, draftId, snapshot }): NoteDocument;
saveNote({ id, expectedRevision, mutationId, patch }): SaveNoteResult;
trashNote({ id, expectedRevision, mutationId }): NoteDocument;
restoreNote({ id, expectedRevision, mutationId }): NoteDocument;
```

`patch` 支持标题、正文、标签、主题、置顶；省略=不变，`research_interest_id: null`=取消主题，`tags: []`=清空标签。返回整个已提交文档及 revision，不让前端猜更新时间。列表仅返回 ID、标题及排序/筛选所需元信息，界面只渲染标题；搜索可返回正文命中位置供打开后定位，正文按 ID 单独读取。

**保存事务**：校验 mutationId → 用 expectedRevision 检查当前行 → 校验主题及附件引用 → 单次更新全部字段并递增 revision → 写必要检查点和事件任务 → 提交 → 返回。版本不符返回 `conflict` 和当前版本；不存在、已删除、校验失败各有错误类型；禁止覆盖。取消主题是明确的 null，不能与省略字段混淆。

同一笔记前端只有一个在途保存；保存 v3 时继续产生 v4，v3 响应只确认对应 edit_seq，随后提交 v4。revision 是数据库版本，edit_seq 是本窗口编辑序号，两者不可混用。失败时保留最后确认版本和最新草稿；冲突提供「查看差异 / 另存副本 / 使用当前数据库版本」，后一项替换前先保留本地草稿。

**草稿与关闭**：输入后短间隔（建议 250ms）持久化快照，自动保存建议 800ms；两项写入均按 edit_seq 条件更新，迟到响应不删新草稿。草稿表使用独立轻量事务。切换前等待草稿确认，正常窗口关闭由 Tauri 关闭事件协调；异常断电只承诺保留最后一次已确认快照，不承诺尚未写入的最后几个按键。正式保存与草稿清理通过 draftId/已确认 edit_seq 匹配，新建重试不能创建第二篇笔记。

**副作用**：embedding、长期记忆、Wiki、图谱刷新不阻塞正文成功。按 noteId+revision 合并任务，只对当前版本落索引；旧 embedding 请求迟到必须被拒绝。编辑会话内合并记忆记录，避免自动保存每秒生成事件；持久任务重试与索引失败有独立状态。

**搜索**：先在 SQL 中过滤主题、来源、标签、回收站，再检索排序和游标分页；排序用 `pinned_at/updated_at/id` 稳定决胜。关键词默认离线可用；中文短词先提供可靠的本地子串匹配并用固定集测性能，再决定是否采用 FTS/tokenizer；不能把英语分词行为当成中文全文搜索。语义结果必须在同范围召回，明确展示受限结果数。

**附件**：保留 `xynoteasset://{noteId}/{fileName}`；Rust 验证 URI 和路径只落在受控目录，检查 traversal 与软链接逃逸；读取返回已验证资源。新附件先暂存，文件落盘成功再允许提交引用；崩溃后清理孤立暂存。包含附件的导出生成 Markdown+assets ZIP 并重写为包内相对路径；纯 Markdown 导出明确附件范围。回收站和版本引用仍存在时不回收资源。

### 7.7 路由、迁移及其他写入入口

- 规范入口建议 `/knowledge?view=notes&scope=...&note=...`；`/notes/new` 与 `/notes/:id` 保留兼容，同样组合工作区。FocusLayout 使用所在主题与来源上下文，不硬跳全局知识库。
- 查询范围与选中项进 URL；列表滚动、正文位置、偏好保存在桌面视图状态。新建草稿使用独立 draftId，并在正式创建后 replace 为真实 noteId。
- 迁移前生成可恢复数据库快照，并保存附件清单；逐步增加字段/表，禁止重写正文或重建笔记 ID。测试空库、旧库、失败恢复和重复启动。
- 现有命令先保留适配层；create/update/move、论文分析、对话工具、导入和主题删除路径都需要写入审计。所有写入统一经过新领域服务；旧客户端写入也必须递增 revision，使新编辑器能发现冲突。
- 现有同步服务也处理 knowledge_notes，本轮必须验证新字段、软删除 tombstone、版本历史及旧客户端行为。草稿不参加同步；跨设备冲突不能用设备本地递增 revision 直接决定胜负，应由同步合并产生本地新版本并保留冲突副本。
- 在同步协议兼容测试通过前，不能把回收站作为完整发布功能开放给启用了同步的用户；分支验证可先关闭新 UI，但不能靠全量恢复旧数据库丢弃上线后的编辑。
- 上线回滚优先通过功能开关回到旧兼容外壳，新数据由支持 revision/deleted_at 的适配层继续读写；不能回退到会绕过软删除过滤的旧二进制。历史数据快照只用于明确的数据恢复场景。

## 8. 发布与验证计划

阶段按验收门槛推进。以下工作量仅为排期前估算，以 1 位前端和 1 位 Rust 工程师投入估计，不是交付承诺。

| 阶段 | 范围 | 预估 | 退出条件 |
| --- | --- | --- | --- |
| A：基线与技术验证 | 固定旧笔记语料、主流程测量、编辑器兼容验证；确认同步写入路径和关闭事件 | 2–3 个工作日 | 编辑器采用/暂缓决定有样本依据，形成回归清单 |
| B：可用闭环（首发） | 拆分服务和会话；按 ID 读取、事务保存、版本与草稿；列表正文同屏、阅读/编辑切换、本地范围搜索；替换论文入口薄壳 | 7–10 个工作日 | 全部保存故障用例通过，主要入口体验一致，无内容回归 |
| C：整理与恢复 | 置顶、批量归档、标签、可恢复删除、版本恢复、附件导出；同步及 RAG/Wiki 删除语义 | 4–6 个工作日 | 恢复不改 ID、不丢附件；普通检索不召回回收站；同步兼容通过 |
| D：编辑体验完善 | 若 A 通过则 B 已启用可视化编辑，否则此时完成；大纲、引用定位、精细阅读位置 | 3–5 个工作日 | 内容矩阵、输入法、长文、键盘与窄窗验收通过 |

优先建立同一领域服务和薄适配层，再切换工作区；避免新旧编辑器各自接入一套保存逻辑。B 中现有不可恢复删除暂保留明确确认，C 完成后统一替换为回收站，不提前展示不能兑现的恢复承诺。

必验场景：

1. 首次新建无标题笔记、只写标题、完全空白离开；创建响应丢失后重试只得到一篇。
2. 保存期间继续输入、修改主题/标签、保存失败重试；回执不能清除新改动。
3. A→B 快速切换、返回、刷新、FocusLayout 切换、深链接直接打开；文档不串内容、不丢位置。
4. 两窗口同时编辑、同步或 AI 写入、编辑中删除；检测版本冲突，草稿可另存。
5. 草稿写入失败、磁盘满、正常关闭、异常退出；已确认状态与实际恢复内容一致。
6. 中文关键词在某主题中有超过全局 top_k 的匹配，分页仍能找到；离线搜索不等待外部服务。
7. 旧 Markdown 样本只读不变、编辑后无语义丢失；所有入口图片、公式、代码、引用一致。
8. 软删除、恢复、永久删除、导出附件、主题删除与同步；图谱/Wiki/RAG 不把已删来源当有效证据。
9. 快速连续编辑触发索引请求乱序；只有当前版本索引生效，保存不等待索引。
10. 320/768/1024/1440px、浅/深主题、键盘与中文输入法；窄窗不强制双栏编辑。

代码落地每个结构性阶段至少运行 `pnpm --filter @research-copilot/desktop type-check`；共享契约/跨工作区行为变化运行 `pnpm type-check` 和 `pnpm lint`；Rust 事务、迁移、幂等和版本检查补针对性测试。界面运行态与 Tauri 故障测试不可由前端类型检查替代。

阶段 B 第一批代码已落地：知识库笔记改为范围导航、纯标题列表和正文同屏；已有笔记默认阅读并可原位编辑；新建草稿会在本机保留并自动保存；关键词搜索默认在已加载笔记中离线完成；标题、正文和研究主题改为一次事务保存；独立笔记路由改为按 ID 读取。回收站、数据库 revision/冲突处理、持久草稿表、版本历史、附件索引和编辑器兼容性验证仍属于后续批次。

设计原型通过浏览器的新建、编辑后切换返回、搜索、详情展开、窄屏返回列表检查，并在 320/360/768/1024px 检查容器无横向溢出。第一批业务代码通过 Desktop type-check、生产构建、相关组件与保存竞态测试以及 Rust `cargo check`。该检查还不等同于完整 Tauri 交互、编辑器内容兼容或产品性能验收。
